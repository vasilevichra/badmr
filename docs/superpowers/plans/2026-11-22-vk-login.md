# Вход через VK (привязка к существующему аккаунту) — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** вход через VK ID как альтернативный способ входа для существующих аккаунтов: привязка из карточки игрока, автопривязка по подтверждённым email/телефону, без регистрации новых аккаунтов.

**Architecture:** OAuth 2.1 + PKCE на `id.vk.com` без новых npm-зависимостей: обобщённый модуль `src/services/oauth.ts` (state/nonce/PKCE, верификация `id_token` по JWKS, user_info) + три роута в `src/routes/auth.ts` (`GET /vk`, `GET /vk/callback`, `POST /vk/unbind`). Логин — существующим passport-механизмом (`req.login`, serializeUser хранит `{id, username}`), ошибки — существующим flash-механизмом `sess.messages`.

**Tech Stack:** Express 5, node:crypto (RS256 + JWKS-кэш), express-session (SQLite), node:sqlite через `src/db.ts`/репозитории.

**Spec:** `docs/superpowers/specs/2026-11-22-vk-login-design.md` (читать вместе с планом; решения заказчика зафиксированы там).

## Global Constraints

- Новых npm-зависимостей нет; импорты всегда с расширением `.ts` (исполнение через `node --experimental-strip-types`, сборки нет).
- Секреты (`VK_CLIENT_ID`, `VK_CLIENT_SECRET`) — только из `process.env`; в коде, fixtures и тестах реальных токенов нет.
- Комментарии и идентификаторы — на русском; комментарий объясняет инвариант, а не повторяет код.
- SQL — через `src/db.ts` (`db.get<T>` / `db.all<T>` с дженериком на месте), репозитории — синглтоны `static _instance`.
- Перед завершением: полный `npm run test` зелёный; `npm run typecheck` — не больше 43 ошибок (текущая база).
- Redirect URI в приложении VK: `https://badmr.ru/api/auth/vk/callback` (роутер auth смонтирован на `/api/auth` — `app.ts:137`).

## Review Focus

Входы/сбои, которые спекой подразумеваются, но тестами задач могут быть не накрыты:

1. Email из VK указывает на пользователя A, телефон — на другого B → отказ с подсказкой ручной привязки, не вход в A. Тест в Задаче 4.
2. У пользователя уже есть `vk_id`, повторное «Привязать» → отказ «VK уже привязан», чужая привязка не перезаписывается. Тест в Задаче 4.
3. Callback с чужим/просроченным `state` или `nonce` → отказ с сообщением, не 500 и не вход. Тест в Задаче 2.
4. VK вернул отформатированный телефон `+7 (900) 123-45-67` → нормализация к `+79001234567`, совпадение в базе находится. Тест в Задаче 1.
5. `VK_CLIENT_ID` не задан (dev без приложения) → кнопка VK не рендерится, `GET /api/auth/vk` редиректит на страницу входа с сообщением, не 500. Тесты в Задачах 4–5.

### Task 2: `oauth.ts` — startAuth / handleCallback (PKCE, state/nonce, id_token, user_info)

**Files:**
- Modify: `src/services/oauth.ts`
- Test: `tests/services/oauth.test.ts` (добавить describe)

**Interfaces:**
- Consumes: `normalizeEmail`/`normalizePhone` из Задачи 1.
- Produces:
  - `configured(): boolean` — заданы ли `process.env.VK_CLIENT_ID` и `VK_CLIENT_SECRET`.
  - `startAuth(session: Record<string, unknown>, intent: 'login' | 'bind'): string` — генерирует `state`/`nonce` (crypto.randomBytes hex 16+), PKCE `code_verifier` (43–128 символов из [A-Za-z0-9-._~]), кладёт в `session.oauth = {state, nonce, verifier, intent}`, возвращает URL `https://id.vk.com/authorize?...` с `response_type=code`, `client_id`, `redirect_uri` (`https://badmr.ru/api/auth/vk/callback` — из `process.env.VK_REDIRECT_URI` или дефолт), `scope=email phone`, `state`, `nonce`, `code_challenge` (S256 от verifier) и `code_challenge_method=S256`.
  - `handleCallback(req: { query: { code?: string; state?: string }; session: Record<string, unknown> }): Promise<VkProfile>` — сверяет `state` с сессией, чистит `session.oauth`; обменивает код (`POST https://id.vk.com/oauth2/get_token`, body form: `code`, `client_id`, `client_secret`, `redirect_uri`, `code_verifier`, `state`); верифицирует `id_token` (RS256 по JWKS `https://id.vk.com/.well-known/jwks`, кэш в памяти процесса с TTL 1 час; проверки `iss`, `aud` = client_id, `exp`, `nonce`); запрашивает `POST https://id.vk.com/oauth2/user_info` с `access_token`; возвращает `{ vkId: string; email: string | null; phone: string | null }` (нормализованные). Любая проверка провалена → бросает `Error` с русским сообщением.
  - `export interface VkProfile { vkId: string; email: string | null; phone: string | null }`.
  - Для тестов: JWKS-кэш сбрасываемый — `resetJwksCache()` (публичный, используется только тестами).

**Interfaces:**
- Consumes: `OAuthService` (`configured`, `startAuth`, `handleCallback`, `VkProfile`), `UserService.getByVkId`, `getContactsMatches`, `setVk` из задач 2–3.
- Produces: HTTP-поведение (ниже); flash-сообщения — `req.session.messages = ['...']` + `res.redirect('/api/auth/login')` (механизм `app.ts:64-71`).
- Логика `GET /vk`: если `!oauthService.configured()` — flash «Вход через VK сейчас недоступен» и redirect на `/api/auth/login`; иначе intent = `req.user ? 'bind' : 'login'` (залогиненный, нажавший кнопку в карточке, привязывает; не залогиненный — входит), `redirect(startAuth(session, intent))`.
- Логика `GET /vk/callback` (порядок веток фиксирован спекой):
  1. `try { profile = await oauth.handleCallback(req) } catch` → flash с `err.message`, redirect `/api/auth/login`.
  2. intent из `session.oauth` уже очищен — если `req.user` есть и intent был `bind`: если `getByVkId(profile.vkId)` существует и это другой id → flash «этот VK уже привязан к другому аккаунту»; иначе если у текущего `user.vk_id` непустой → flash «VK уже привязан»; иначе `setVk(user.id, profile.vkId)` + redirect `/` (в карточку). Сессия истекла (`bind` без `req.user`) — продолжаем как `login`.
  3. intent `login`: `getByVkId(profile.vkId)` → найден: `req.login({id, username: user.email}, ...)` → redirect `/` (как в `router.post('/signup'`, `src/routes/auth.ts:83-88`). `username` брать из строки пользователя (SELECT email по id).
  4. Автопривязка: `matches = getContactsMatches(profile.email, profile.phone)`; ровно один уникальный id в массиве → `setVk(id, profile.vkId)` + логин как в п.3; иначе flash «этот VK не привязан: войдите почтой и привяжите в карточке игрока» + redirect `/api/auth/login`.
- `POST /vk/unbind`: `ensureLoggedIn()`, `setVk(req.user.id, null)`, ответ — `res.promise(Promise.resolve())` (json для ajax-вызова из карточки).
