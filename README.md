# Бадминтон и ром

[![badmr CI](https://github.com/vasilevichra/badmr/actions/workflows/badmr.ci.yml/badge.svg)](https://github.com/vasilevichra/badmr/actions/workflows/badmr.ci.yml)

Программа для подбора игроков по рейтингу для равных и захватывающих матчей.
Суть игры с выбором по рейтингу напарника и соперников в том, чтобы сделать игры максильмально
интересными и напряжёнными, чтобы борьба велась за каждое очко. В таких условиях у **любителей** быстро
растёт уровень игры, появляется интерес к развитию, начинают задаваться вопросы.
А **тренер** освобождается от мучительного выбора расстановки игроков на корте по уровню
и по личному предпочтению игроков с кем они хотят или не хотят играть.

## Глоссарий
- `Δ` - Максимальная разница в сумме рейтингов пар при их формировании (дельта).
Настраиваемый предел: `tournament_settings.delta`.

### Важные замечания:
1) Напарник назначается по рейтингу, а не по желанию;
2) Соперники подбираются, таким образом, чтобы сумма рейтингов пар не превышала `Δ`.

## Рейтинг
Дельта за игру: `(rating_diff_limit − разница средних рейтингов команд) / rating_diff_divisor`,
у проигравшей пары — с обратным знаком. Если разница средних рейтингов команд не меньше
`rating_diff_limit`, дельта за игру не начисляется.

Калибровка: если рейтинг игрока неактуален (не обновлялся дольше `calibration_fresh_days`,
задан вручную или отсутствует), к следующим `calibration_matches` матчам применяется
множитель K, затухающий от `calibration_boost` до 1; изменение рейтинга за матч
ограничено `calibration_cap`.

Пересчёт: при изменении или удалении матча рейтинг каскадно пересчитывается по всем
завершённым матчам его участников, сыгранным позже изменённого (по хронологии);
список затронутых игроков расширяется итеративно, так как новые дельты влияют
на рейтинги их соперников в следующих матчах. История изменений хранится в таблице
`rating`: каждая запись привязана к матчу (`match_id`) и хранит рейтинг до игры
(`previous`) и дельту (`delta`); там же — признаки калибровки (`stale`, `series`).

## Алгоритм

Подбор работает по раундам: по кнопке «Подбор» система собирает матчи сразу на все
доступные корты. Пайплайн: готовые игроки → эффективная дельта → кандидаты → сборка раунда.

### 1. Готовые игроки (вьюха `ready`)

В подбор попадают участники турнира (доступные, не архивированные), у которых сейчас
нет незавершённого матча, а число сыгранных матчей меньше ограничения `matches`
(0 — без ограничений). Рейтинг игрока — последняя запись таблицы `rating`
(`previous + delta`). Для каждого игрока известны:

- `matches` — сколько матчей он сыграл на турнире;
- `played` — играл ли он в одном из последних `N` матчей турнира, где
  `N = доступные корты + незавершённые матчи` (прокси «недавно выходил на корт»,
  основа ротации отдыха);
- `wins` — выигранные матчи турнира; `won` — исход последнего матча.

### 2. Эффективная дельта (`delta_auto`)

При выключенной `delta_auto` берётся настройка `delta`. При включённой — доля матчей
в три игры среди последних `delta_auto_window` завершённых матчей турнира сравнивается
с порогами: ниже `delta_auto_lower%` — матчи односторонние, дельта сужается до
`⌈delta × 0.85⌉`; выше `delta_auto_upper%` — слишком много трёхигровых, дельта
расширяется до `⌊delta × 1.15⌋`. Результат всегда ограничен диапазоном `[10, 300]`.

### 3. Кандидаты

Строятся все допустимые матчапы «пара против пары» из четырёх разных готовых игроков.
Кандидат отсеивается, если:

- сумма-разница рейтингов команд больше эффективной дельты (`diff > Δ`);
- `proc > 0` и один из игроков пары превышает её средний рейтинг более чем на `proc%`:
  `max(r1, r2) > avg × (1 + proc/100)`;
- включена система `fifty` и фаворит матчапа играет «вниз».

Фаворит по моментуму (система 50%): у какой пары больше побед в последних матчах
(сначала по исходу последнего матча, при равенстве — по доле побед `wins/matches`).
Если таких фаворитов нет (равные по моментуму) — матчап нейтрален. Матчапы, где
фаворит играет против более слабой пары, отбрасываются; если после этого кандидатов
не осталось, фильтр игнорируется (иначе подбор может вообще ничего не выдать).

У каждого кандидата считаются поля приоритета:

| Поле      | Куда  | Смысл                                                                                                                                                             |
|-----------|-------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `matches` | min   | Сумма сыгранных матчей всех четырёх игроков — выравнивание игровой нагрузки                                                                                       |
| `rematch` | min   | Штраф повторных встреч (0–3): напарники из одной пары или точный состав из четырёх встречались в последних `rematch_window` завершённых матчах турнира             |
| `played`  | min   | Сумма `played` — ротация отдыха: меньше «недавно игравших» в раунде                                                                                                |
| `balance` | max   | Предсказанная вероятность матча в три игры — конкурентность                                                                                                        |
| `diff`    | min   | Сумма-разница рейтингов команд — равенство пар                                                                                                                     |
| `friends` | max   | Сумма «шансов» пар: винрейт совместных доигранных матчей напарников (вместе не игравшие дают 0) — свозит тех, кто уже выигрывал вместе                             |

**Модель конкурентности.** Вероятность «матча в три игры» — логистическая:
`P = σ(a − b1·avgDiff/10 − b2·spread/100)`, где `avgDiff = diff/2` — разница средних
рейтингов команд, `spread` — максимальный разброс рейтингов внутри одной из пар.
Коэффициенты подгоняются по истории самого турнира (записи `rating` дают рейтинги
игроков до матча): при минимум 20 завершённых матчах — градиентный спуск по бинарной
кросс-энтропии (400 итераций, старт из дефолта `a=0, b1=b2=0.3`); при меньшей истории —
дефолт. Коэффициенты `b1, b2` ограничены снизу малыми положительными значениями,
чтобы данные не «перевернули» зависимость (больше разница — меньше трёхигровых матчей).

### 4. Сборка раунда

Раунд — набор непересекающихся матчей (каждый игрок не более одного матча за раунд),
не более `courts` штук. Сборка детерминирована: случайности нет, равные варианты
разрешаются порядком перечисления кандидатов.

1. **Жадный старт.** Корт за кортом берётся лучший кандидат по лексикографическому
   порядку полей приоритета (см. таблицу выше; при равенстве всех полей — первый
   по перечислению). При этом предпочтение отдаётся кандидатам, к которым существует
   непересекающееся дополнение: иначе лучший одиночный матч может заблокировать
   заполнение остальных кортов и раунд недоберёт матчи. Если расширяемых кандидатов
   нет, берётся просто любой допустимый.
2. **Локальный поиск** (до локального оптимума, максимум 100 улучшений):
   - *добавление матча* — если корты ещё не заполнены, добавляется любой подходящий;
   - *замена матча* — один выбранный матч меняется на альтернативный, если ключ
     решения всего раунда улучшается;
   - *перегруппировка пары матчей* — два выбранных матча (8 игроков) переигрываются
     во все возможные другие пары разбиений, если это улучшает ключ.

Ключ решения раунда: `[−число матчей, агрегаты полей приоритета (с учётом
направления), отсортированные сигнатуры составов]`. Минимизация «−число матчей»
гарантирует, что при прочих равных раунд с большим числом матчей лучше; сортировка
сигнатур делает равными симметричные перестановки матчей между кортами — локальный
поиск не «дёргает» эквивалентные решения.
